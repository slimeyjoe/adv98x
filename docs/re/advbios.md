# AdvBIOS 0.54 as shipped with NOVA (`NV.OV1`)

Service layer under the Adv98V 1.70.54 interpreter (`NV.OVL`): graphics, text, mouse, files, timing, sound.
This document describes NOVA's build; it is the specification of what a replacement engine has to provide
to the interpreter and to the `.TCM` plug-ins.

Conventions

* Addresses are `SEG:OFF` relative to load base 0 of the decrypted, unpacked image
  `resources/derived/exe/NV.OV1` (file offset = 200h + SEG*16 + OFF). `DS:xxxx` means DGROUP, segment 3018.
* **verified** = read in NOVA's code (or checked against NOVA's data files); **inferred** = reasoned from
  the code, from PC-98 hardware/BIOS conventions, or taken from the reference without re-deriving.
* Names are in `listing/advbios-names.tsv` (generated by `re-tools/advbios_map.py`). A listing can be
  regenerated into `resources/derived/listing/advbios.lst` with
  `re-tools/dis16.py resources/derived/exe/NV.OV1 --names docs/re/listing/advbios-names.tsv --out …`.
* Reference: Valley Bell's annotated disassembly of the AdvBIOS 0.54 build of *Dengeki Nurse*
  (`Adv98V/DengekiNurse/ADVBIOS.DEC2.asm`, <https://github.com/ValleyBell/>, CC-BY-SA docs / GPL-2 code).
  About 95 labels (interrupt handlers, a few API functions, strings) come from there and are marked `VB` in
  the names table; everything else — in particular the meaning of almost all function numbers — was worked
  out on NOVA's binary for this document. Where a VB name was not re-checked this is said explicitly.

## 1. Binary layout

MZ header 200h bytes, 71 relocations, entry 0000:1732, image 30750h bytes (**verified**). The relocated
words only ever hold nine segment values, which give the segment map:

| segment | image range | size | contents |
|---|---|---|---|
| 0000 | 00000–01AAF | 1AB0h | start-up, INT F1h (system), INT F6h (text), INT F2h (files), INT 24h, C-runtime-like glue |
| 01AB | 01AB0–028FF | E50h | "Mouse Interface Routine Ver.0.70 / Copyright(C) Tuneup 1988,92" (string 01AB:000E, credit "Thanks to …" 01AB:005A): INT 33h + bus-mouse IRQ; its variables live in this segment (01AB:016E–09D7), default cursor 01AB:09D8 |
| 0290 | 02900–0327F | 980h | INT F3h (graphics: GPC display, animation cells, palette); tables 0290:045C–059B |
| 0328 | 03280–04E8F | 1C10h | sound: `USDdrv` (INT F4h front end, 0328:0000–0556) and `USDtrap` (YM2203 driver + sequencer, 0328:0557–1C07, "Copyright (C) K.KONDO 1991 All rights reserved...V01.02" at 0328:0583) |
| 04E9 | 04E90–14AEF | FC60h | zero-filled work segment of INT F3h: variables 0000–0453, GPC file buffer 0454–FC53 |
| 14AF | 14AF0–24AEF | 10000h | zero-filled: two 32 KB animation banks (0000, 8000) |
| 24AF | 24AF0–2B0EF | 6600h | zero-filled: animation-frame decode work area |
| 2B0F | 2B0F0–3017F | 5090h | zero-filled: music file (0000, 3000h bytes), SE file (3000, 2000h bytes), sound state 5000– |
| 3018 | 30180–3074F | 5D0h in file | DGROUP: strings, jump tables, initialised variables; BSS 05C6–1C0F is cleared at start (0000:1762); stack top 3018:2410 |

All of this is **verified** (segment values from the relocation table; uses from the code that loads them:
0290:003B, 0290:05F0/05F5, 0328:00B0, 0000:01CA …).

The program needs 3018:2410 − image end = 1E40h bytes beyond the file image. Note: the derived file's MZ
`e_minalloc` is 2D7Bh paragraphs; that is the value of the EXEPACK-ed original carried through the
unpacker, not what the unpacked code needs (**inferred**; the Dengeki Nurse reference file has 1E5h).

## 2. Start-up, residency, shutdown

### 2.1 Entry `start` 0000:1732 (**verified**)

| step | code | effect |
|---|---|---|
| 1 | 1732–173D | SS:SP = 3018:2410 |
| 2 | 173E–1758 | INT 21h AH=4Ah: shrink the program's memory block to end at the stack top (frees the rest for the child). Failure → message 0 ("cannot allocate memory."), exit FFh |
| 3 | 175A | PSP segment → DS:03C4 |
| 4 | 1762–1774 | clear BSS DS:05C6–1C0F |
| 5 | 1775 → 198E `parse_cmdline` | split PSP:80h into argc (DS:1C02) / argv (DS:1C04, on the stack) |
| 6 | 177A → 1A92 `VerifyUserName` | see §2.3 |
| 7 | 177D → 179E `selfcheck_banner` | checksum over DS:0000–00DF (the banner/copyright strings): `dx += b; dh ^= b` per byte must give A177h, else message 1 ("null pointer assignment.") and exit FFh |
| 8 | 1787 → 17B6 | atexit list empty |
| 9 | 1794 → 0010 `main(argc, argv)` | §2.2 |
| 10 | 179B → 17E0 `exit_with_code` | run the atexit list (only entry: `DeinitAll` 0000:00DC), repeat the banner checksum, INT 21h AH=4Ch |

### 2.2 `main` 0000:0010 → `DoMainInit` 0000:004E (**verified**)

1. `SetupIntVec06_05` 0000:18C4: INT 05h (COPY key) and INT 06h (STOP key) → a bare `iret` (0000:191A).
2. Print `ESC[2J ESC[>1h ESC[>5h` + "AdvBIOS for PC-9801V  Version 0.54" + copyright (DS:0070, 00E0, 0095):
   clear text screen, function-key row off, cursor off. Short delay loop.
3. Set bit 5 of BIOS byte 0000:0500 (0000:0076; cleared again at exit, 0000:0145).
4. Install, in this order: INT F1h (0000:0150), mouse INT 33h + IRQ (01AB:0086), INT F3h (0290:0004),
   INT F6h (0000:08B0), INT F2h + INT 24h (0000:11B0), sound (0328:001C).
5. Register `DeinitAll` with `atexit_add` (0000:17BC).
6. `init_screen_state` 0000:00A2: `out 6Ah,01h` (16-colour mode), `out 68h,01h` (text attribute bit 4 =
   simple graphics, needed by the curtain effect §5.6), `out 6Ah,41h` (purpose not determined, see §11),
   INT F3h AH=10h (default palette), AX=1100h (brightness 0 = black), then for access page 1 and 0
   (`out A6h`) INT F6h AX=0C00h (clear to colour 0), `out A4h,0` (display page 0), INT F3h AX=110Fh (full
   brightness), INT 33h AX=0, INT F1h AH=06h DX=0 (default beep pitch).

Then `main` calls `spawn` 0000:180C with the program name at DS:00EE = **"NV.Ovl"** and a command tail
rebuilt from AdvBIOS's own arguments (0000:1864; no arguments → empty tail). `spawn` masks IRQ0
(`in 02h / or 1 / out 02h`, 0000:1848) and does INT 21h AX=4B00h with the parameter block at DS:1BEA.

So AdvBIOS is **not a TSR**: it is the parent process of the interpreter and simply stays in memory, with its
vectors installed, while `NV.OVL` runs as its child. When the child terminates, `main` returns, the atexit
list runs `DeinitAll` and AdvBIOS exits to its own parent (`NV.COM`, which is `SHELL=` in CONFIG.SYS and
EXECs "NV.ov1"; **inferred** from the strings and INT 21h calls in NV.COM, not analysed further).

The interpreter detects AdvBIOS by reading the INT F1h vector (INT 21h AX=35F1h in NV.OVL, **inferred**
from a byte scan): the handler starts `jmp short $+12h` followed by the signature `"++ AdvBIOS98 ++",0`
at handler+2 (0000:01AA, **verified**).

Quirk worth knowing: because of the IRQ0 mask set by `spawn`, the 20 ms tick (§7) does not run in the
child until the first INT F2h call returns (every INT F2h call unmasks IRQ0 on exit, 0000:1284)
(**verified** in code; consequence **inferred**).

### 2.3 User-name / confidentiality check (**verified**)

* DS:03C6–0545: the "Confidentiality Notice" (《機密保持に関する注意》 … 使用者名：ＮＯＶＡぱんだはうす …
  何かキーを押して下さい。), stored XOR FFh. The user name inside it sits at DS:0500.
* DS:0531: plain copy of the user name, 10 words: **"ＮＯＶＡぱんだはうす"**.
* `VerifyUserName` 0000:1A92 compares the 10 words at DS:0500 XOR FFFFh with DS:0531. Mismatch →
  `ShowErrorMsg(-1)` (index clamped to 2 → "cannot run on this machine.") and `exit_with_code(1)`.
* `show_confidential_notice_unused` 0000:1A4E (no caller): checksums the 180h notice bytes
  (`dx += b; dh ^= b; rol dx,1`) against the word at DS:0546, then prints the decoded notice through
  INT 21h AH=06h and waits for a key (AX=0C08h).
* Runtime error messages ("??? runtime error: " + one of four `$` strings) are selected through
  DS:0548 (`errorMsgList`) by `ShowErrorMsg` 0000:1A28.

None of this needs to be reproduced; it has no effect on the services.

## 3. Calling convention common to INT F1h / F2h / F3h / F6h (**verified**)

Each handler does `pusha; push ds; push es; mov bp,sp`, enables interrupts if the caller had them enabled,
clears the caller's carry flag in the stacked FLAGS, loads DS=ES=DGROUP (INT F3h: DS=ES=04E9), and
dispatches on **AH** through a jump table; out-of-range AH goes to an entry that only sets carry.
Results are written into the stacked register image, so:

* every register that is not documented as a result is preserved (including AX);
* errors are reported by **CF=1** (a function that does not mention CF returns CF=0);
* pointer arguments use the *caller's* DS/ES (the handlers fetch them from the frame: `[bp+2]`=DS,
  `[bp+0]`=ES).

Frame offsets, useful when reading the listing: +00 ES, +02 DS, +04 DI, +06 SI, +08 BP, +0C BX, +0E DX,
+10 CX, +12 AX, +18 FLAGS.

Jump tables: F1h DS:0108 (AH 00–11h), F6h DS:01BE (00–13h), F2h DS:01E8 (00–08h), F3h 0290:0068
(00–16h, plus the special case AH=FFh).

Used-by column below: `O` = called by NV.OVL, `T` = by a NOVA `.TCM`, `B` = by AdvBIOS itself; found by
scanning for `mov ah/ax,imm … int nn` patterns, so a missing mark is not proof of non-use.

## 5. Graphics and text

### 5.1 VRAM model (**verified**)

* 640×400, 16 colours, four planes at A800/B000/B800/E000 (DS:018C..0192), 80 bytes per line; offset =
  y·80 + x_byte. Text VRAM at A000 (characters) / A200 (attributes), DS:0194.
* AdvBIOS only touches the page registers during init and exit (`out A6h` access page 1 then 0, `out A4h`
  display page 0; 0000:00B5–00C9, 00EE–0102). All F6h drawing goes to segment A800… of whatever access page
  is current. NV.OVL contains no `out A4h/A6h` either (byte scan), so with this game everything is drawn
  on page 0 unless a plug-in switches pages (**inferred**).
* INT F3h AH=01h does not use fixed segments: the four destination plane segments come from the caller's
  parameter block, so an image can be decoded into ordinary memory as well as into VRAM.
* GRCG is used for text (RMW mode C0h) and fills (TDW mode 80h) through ports 7Ch/7Eh; EGC (ports
  4A0h–4AEh) only for vertical scrolling when detected. No AdvBIOS service exposes block get/put/copy;
  the mouse cursor's private save/restore (01AB:0DA0/0DCE) is the only such code.

### 5.2 Character drawing — INT F6h AH=09h `apiF6_09_DrawChar` 0000:0AB0 (**verified**)

Input DX. Glyphs always come from the machine's kanji ROM through INT 18h AH=14h (buffer DS:1800: byte 1 =
glyph width in bytes, 1 or 2; 16 rows follow, 1 or 2 bytes each). KCG dot-access mode is selected once at
install (INT 18h AX=1B01h).

| DX | action |
|---|---|
| DH≠0 | Shift-JIS → JIS (`ShiftJIS2JIS` 0000:024C), full-width 16×16 |
| 000Dh | newline only |
| 0020h–007Eh | JIS 29xxh with xx = the character code → **half-width 8×16 glyph** |
| 00A0h–00DFh | JIS 2Axxh with xx = code − 80h → half-width katakana |
| other 1-byte values | ignored |

So half-width (ASCII) text needs no font of its own: it is the ROM's half-width row 29h/2Ah, 8 pixels
wide, advancing one column. That the BIOS returns width 1 for these rows is PC-98 behaviour (**inferred**);
the code handles both widths generically.

Sequence:

1. If bold (DS:01A5) → `MakeCharBold` 0000:0BFC: every row is ORed with itself shifted right one pixel
   (across both bytes for full-width). Quirk: when the rightmost pixel of the row was set, bit 1 of the
   last byte is set too.
2. Lip-sync hook: if the text colour equals trigger colour 0 / 1 (DS:0182/0183) the pending counter of
   animation slot 0 / 1 is incremented (§5.4).
3. Wrap before drawing: a full-width glyph with cursor x ≥ window x1 first does a newline.
4. Draw at A800:(y·80 + x), 16 rows: GRCG RMW with the tile registers set from the colour bits, i.e.
   set glyph pixels take the text colour, clear pixels leave the background untouched.
5. x += width; if x > x1 → newline. Newline (`text_newline` 0000:0C7C): x = x0; y += 20; if y + 20 ≥ y1
   then y = y0 (wraps to the top; there is **no automatic scroll or page wait** — that is the
   interpreter's business). **Line pitch is 20 pixels** for 16-pixel glyphs.
6. If the beep length (DS:01AA) ≠ 0: beep for that many ticks unless the character is punctuation
   (JIS 2121–212A, 2144, 2145); the wait is always there.
7. If the character delay (DS:01A6) ≠ 0: wait that many ticks, +25 ticks after punctuation. Both waits
   end early when skipping is allowed (AH=07h flag) and SHIFT is held or the right button is down.

Defaults: window (0,0)–(79,399), cursor (0,0), colour 15, bold off, delay 0, skippable, no beep.

### 5.3 GPC images — INT F3h AH=00h/01h/02h

Decoder internals are documented elsewhere; this is the calling interface (**verified**).

1. AH=00h → ES:BX (04E9:0454), CX (F800h). Caller reads the whole `.GPC` file there.
2. AH=01h with DS:SI → parameter block, copied to 04E9:0000:

| offset | meaning |
|---|---|
| +0, +2, +4, +6 | destination segments of planes 0..3 (A800h, B000h, B800h, E000h for the screen) |
| +8 | x in bytes; FFFFh = take position (x pixels/8, y) from the file |
| +A | y (only used when +8 ≠ FFFFh) |
| +C | 0 = opaque (`gpc_row_put_opaque` 0290:0136); ≠0 = transparent: pixels of colour 0 leave the destination unchanged (`gpc_row_put_masked` 0290:0192) |
| +E | flags: bit 0 = copy the file's 16 palette words into the palette buffer; bit 1 = then program the hardware (AH=11h with the current brightness, VSYNC wait) |

   Destination offset = y·80 + x; rows are 80 bytes apart (hard-wired). Header fields used
   (`gpc_parse_header` 0290:02DE; checked on NV00.GPC: magic "PC98)GPCFILE   ", +10h = 1, +14h = 30h,
   +18h = 5Ah): word at +10h = interlace count N (rows are stored in N passes, pass k holding rows
   k, k+N, …); dword at +14h = offset of the palette block (4 bytes, then 16 words 0GRB); dword at +18h =
   offset of the image block: width (pixels), height, 6 bytes skipped, x (pixels), y, 4 bytes, then the
   packed rows. Row pipeline: `gpc_row_unpack` 0290:0294 → `gpc_row_unfilter` 0290:0257 → XOR with the
   previous row (`gpc_row_xor_prev` 0290:01F4, skipped for the first row) → put.
3. AH=02h reports x, y, width in bytes, height, N and a far pointer to the palette block.

### 5.4 Animation cells and scripts (lip-sync / blinking) (**verified**)

* Two banks (0/1): the caller loads a cell file to the address given by AH=08h (14AF:0000 / 14AF:8000,
  32 KB each). Bank header: word at +10h = number of frames; dwords at +18h + 4·i = offset of frame i.
  Frame: word interlace count, x (pixels), y, width (pixels), height, then rows packed like GPC rows.
* AH=09h AL=bank, BL=frame character: frame index = BL − B1h (B1h is half-width katakana ｱ, so frames
  are named ｱ, ｲ, ｳ …). Ignored if BL is `.` or space, if the index ≥ frame count, or if bit 1 of the
  mode word DS:0180 is clear. The frame is decoded into 24AF and copied opaquely to all four planes of the
  screen segments A800… (fixed, not the caller's).
* Each bank has a *script* (AH=0Bh, DS:16CE / DS:1764), a *pending counter* (DS:0184 / 0186) and a
  *trigger colour* (DS:0182 / 0183, initially 10h = never).
* `anim_step` 0290:07F4 runs when mode bit 0 is set, once every 2 ticks while one of the waiting
  services polls it (INT F1h 07h/08h/0Ah, or explicitly INT F3h AH=0Fh). For each bank whose counter ≠ 0 it
  takes the next script character: 00h (end) → counter −1, rewind, continue with the first character
  (an empty script stops); space → counter −1, no drawing; `.` → no drawing this step; `~` → draw the
  following character's frame *and* the one after it in the same step; anything else → draw that frame.
* The counter is bumped by text output: every character drawn in the bank's trigger colour adds 1
  (§5.2 step 2), by AH=0Dh, or set by AH=0Ch. Effect: a mouth-flap script plays once per pending
  character while the game waits.

### 5.5 Scrolling — INT F6h AH=10h/11h (**verified**)

`scroll_dispatch` 0000:0EEE, CX steps, one VSYNC wait per step (port 60h bit 5):

* up / down: the rectangle moves by **one pixel line** per step; the vacated line is cleared to colour 0.
  With EGC present the copy uses the EGC (`scroll_v_step_egc` 0000:109A), otherwise four `rep movsb`.
  Rows moved = y1 − y0, width = x1 − x0 + 1 bytes.
* left / right: by **one byte column (8 pixels)** per step over x1 − x0 columns, y1 − y0 + 1 lines; the
  vacated column is cleared to 0.

### 5.6 Text-layer curtain — INT F6h AH=0Fh (**verified**)

A dissolve drawn with PC-98 text-layer semigraphics (attribute bit 4, enabled by `out 68h,01h` at init),
so it hides or reveals the graphics without touching them. The text screen is treated as 160×100 cells
(2×4 per character). Rectangle CH,CL–DH,DL is in those units. For phase p = 0..30 (DS:01B4 = 31), after a
VSYNC, the cells with linear index (row·160 + column) ≡ p or ≡ 61 − p (mod 62) (DS:01B2 = 62) that lie
inside the rectangle are set (AL ≤ 7) or cleared (AL > 7). Setting also writes the attribute
`(colour << 5) | 11h` with colour = AL, remembered for the later clearing call. Cell bit within a character:
`DS:01B6[(column & 1)·4 + (row & 3)]` = 01h…80h. Total duration 31 frames.

### 5.7 Palette, brightness, fades (**verified**)

* Palette buffer 04E9:0022 (16 words 0GRB) + brightness 04E9:0042.
* Hardware output (`apiF3_11_SetBrightness` 0290:038A): for each colour i: `out A8h,i`; `out AAh,T[g]`;
  `out ACh,T[r]`; `out AEh,T[b]` with T = row *brightness* of the 16×16 table at 0290:049C. The table is
  exactly T[L][v] = round(v·L/15) (half up; checked against all 256 entries), so row 15 is the identity
  and row 0 is black.
* There is no fade routine in AdvBIOS: a fade is the caller looping AH=11h with AL = 0..15 (each call
  waits one VSYNC). AdvBIOS itself dims to min(brightness, 3) while it shows a prompt (§6.4, §8.3, §8.4)
  and restores the old brightness afterwards.

## 6. Input

### 6.1 Keyboard (**verified**)

Polled only, through the PC-98 keyboard BIOS: INT 18h AH=01h (sense, BH≠0 = key waiting), AH=00h (read,
AH = scan code), AH=02h (shift state, bit 0 = SHIFT). Scan codes tested: 1Ch Return and 34h Space
(advance), 15h `Y` / 2Eh `N` (quit prompt). The STOP key is read from the BIOS key-down bitmap
(0000:0536 bit 0) and the keyboard-emulation code reads the bitmap at 0000:052A directly.

### 6.2 Mouse driver, segment 01AB (**verified** unless noted)

* Hardware: PC-98 bus mouse, 8255 at 7FD9h (data) / 7FDDh (control) / 7FDFh (mode, 93h), interrupt rate
  register BFDBh ← 0 (120 Hz), interrupt on IRQ13 = INT 15h (01AB:0402, mask bit DFh at 01AB:0403).
  Bit names of the 8255 are PC-98 convention (**inferred**).
* Interrupt driven: `Int15` 01AB:0A5A runs 120 times per second: counts frames (01AB:042E), reads the X
  and Y deltas (two nibbles each), adds them to the position and clamps to the range; reads the buttons;
  calls the user handler (AX=0Ch); if the cursor is shown and the position changed, erases and redraws it.
* Keyboard emulation (AX=0Dh; NV.OVL switches it on and off): when the hardware reports no movement, held
  keys move the pointer by 1 pixel per interrupt, 4 with SHIFT: → / keypad 6, ← / keypad 4, ↓ / keypad 2,
  ↑ / keypad 8. Return or Space count as the left button, ESC or TAB as the right button. (Key identities
  from the bitmap positions tested at 01AB:0ADC–0BC6 and the standard PC-98 scan-code layout: **inferred**.)
* Cursor shape (AX=09h, `cursor_load_shape` 01AB:0D44): byte 0 = width in bytes (1..5), byte 1 = height
  in lines (1..40), then height×width bytes of AND-mask, then height×width bytes of image. Drawing
  (`cursor_blit` 01AB:0DFC, GRCG RMW): pixels whose mask bit is 0 are drawn, white (15) where the image
  bit is 1, black (0) where it is 0; mask-1 pixels stay. Position is pixel exact; the background under
  the cursor (all four planes, VRAM segments A800…) is saved in 01AB:0436 and restored on erase.
  Default: 16×32 arrow at 01AB:09D8.
* Anything that draws to VRAM under a visible cursor must hide it first; AdvBIOS's own F6h/F3h drawing
  does **not** do that, so it is the caller's duty.

### 6.3 Click maps — INT F1h AH=0Ch / 0Dh (**verified**; file format checked on `CLM/MAP1–4.CLM`)

* File (≤ 7D5h bytes): byte 0 must be 0; byte 1 = x0, byte 2 = y0, byte 3 = width, byte 4 = height, all
  in 8×8-pixel cells; then width×height nibbles, high nibble first, row by row. Size must be at least
  5 + ⌈w·h/2⌉. NOVA's four maps are full screen: `00 00 00 50 32` + 2000 bytes = 2005 bytes.
* AH=0Ch clears the 80×50 map (DS:0EF9, 40 bytes per row) and ORs the file's nibbles into it.
* AH=0Dh: show the cursor; wait until both buttons are up; loop: quit check ≠0 → return 0; right button
  → return 0 unless AL bit 0 is set (then keep waiting); left button → id = map[y/8][x/8]; id ≠ 0 →
  return it; id = 0 → return 0 unless AL bit 1 is set. The cursor is hidden on return. There is no wait
  for release after the click.

### 6.4 Quit prompt — INT F1h AH=0Fh AL=0 (**verified**)

Does nothing (AX=0) if disabled, if DOS reports version 2.00 or 2.12 (INT 21h AH=30h → AX = 0002h / 0C02h;
this is how the game's own boot disk with MEGDOS is recognised — **inferred**), or if STOP is not held.
Otherwise: dim to brightness ≤ 3, save text line 10, show
"《　　終了してもよろしいですか（ｙ／ｎ）？　　》" (DS:012E, attribute C5h), beep 10 ticks, wait for `Y`
or `N`; `Y` sets the sticky flag DS:06BE and returns AX=FFFFh. Line and brightness are restored. Because
all waiting services call this, STOP works anywhere the game waits — when running from DOS 3+.

## 8. Files and disks (**verified**)

### 8.1 Drive model

At install (`SetupIntVecF2` 0000:11B0): boot drive = current DOS drive (DS:186C). *Hard-disk mode*
(DS:186D) = 1 if that drive is not removable (DOS ≥ 3: INT 21h AX=4408h; DOS 2.x other than 2.00: device
type from the DOS-internal table at 0060:006C; DOS "2.00": always floppy). In floppy mode the volume label
of the boot disk is read and its first 10 characters kept as the game's label (DS:186E).

`CopyFileName` 0000:16B4 builds every path as `<drive>:<name>`:

* a leading `X:` in the name is a **logical** drive: index = (X − 1) & 1, so `A:` → 0, `B:` → 1; in
  hard-disk mode the prefix is dropped (index 0);
* drive = boot drive + index; leading backslashes of the rest are removed, so paths are relative to the
  current directory of that drive.

Before every open in floppy mode `MaybeCheckDisk` 0000:1708 calls INT F2h AH=04h with the index taken from
the path and the disk number expected for that index (DS:03C2/03C3, initially 0 and 1).

### 8.2 Disk identification

`read_volume_label` 0000:1496 searches `"@:\*.*"` (DS:0242, `@` replaced by the drive letter) with
attribute 08h (INT 21h AH=4Eh; an extended FCB at DS:0216 with AH=11h on DOS 2.x) and stores the 11-char
label at DS:1878. A disk belongs to the game if the first 10 characters equal the boot disk's;
**disk number = (11th character & 1Fh) − 1**, i.e. labels ending in A, B, C, D are disks 0..3
(NOVA has four disks; the actual label text was not available to check).

### 8.3 Disk-change prompt — INT F2h AH=04h

Hard-disk mode: returns at once. Otherwise loops until the label of drive (boot + index) matches and its
number equals DL; each failure shows a three-line box on text lines 10–12 (columns 14–65, attribute A5h,
saved and restored): "ドライブＸに、ディスク＃Ｙを入れてください。" with X = drive letter, Y = 'Ａ' + DL
(DS:024A/027F/02B4), dims to brightness ≤ 3, waits for all input released and then for any key or button.

### 8.4 Critical errors — `Int24` 0000:1290

For disk errors (AH bit 7 clear) shows on text line 16 "ドライブＸでエラーが発生しました。" plus one of
"ディスクが書き込み禁止です。" (code 0), "ドライブの準備ができていません。" (1, 2),
"データの書き込みに失敗しました。" (0Ah), "データの読み込みに失敗しました。" (0Bh),
"ディスクを確認してください。" (others) (table DS:01FC), beeps for 30 frames, waits for a key or button and
returns AL=1 (**retry**). Non-disk errors return AL=0 (ignore). There is no abort path.

### 9.2 Initialisation and chip detection (**verified**)

`sound_init` 0328:001C: choose the register-access delay by CPU type (INT F1h AH=11h: < 386 a single
`jmp`, 386 five `jmp`s, 486+ six `out 5Fh`); if INT F4h does not already point at a "USDdrv" signature,
run `apiF4_80_Install` → `opn_init` 0328:05BA:

1. Detection: write BFh to SSG register 07h through 188h (address) / 18Ah (data) and read it back; a
   different value → no sound: driver core stays off, INT F4h is **not** hooked.
2. Read register 0Eh (I/O port A): bit 7 set → interrupt vector 14h (IRQ12), clear → vector 15h (IRQ13)
   (only these two board settings are handled). Hook it to `opn_irq`.
3. Key-off the three FM channels (reg 28h), reg 24h ← F7h, 25h ← 01h (timer A), 26h ← DFh (timer B),
   27h ← 30h then 0Fh (clear flags, start both timers with interrupts), unmask the IRQ in the slave PIC.
4. Reset the six channel work areas, volume/fade state.

Then INT F4h is hooked, the built-in sequence at 0328:004C is started (one FM channel, priority 10, an
all-zero voice — presumably just to put the chip in a defined state, **inferred**), 60 VSYNCs are waited
and everything is stopped. Only the YM2203 (OPN: 3 FM + 3 SSG) at 188h is supported — no OPNA rhythm/ADPCM,
no 088h/288h fallback, no beeper music.

### 9.3 Interrupt and timers

`opn_irq` 0328:0720 (**verified**): masks its IRQ, chains to the previous handler, enables interrupts,
acknowledges the timers (`opn_timer_ack`: re-programs timer A if bit 15 of 0328:0574 requests a new
value; rewrites reg 27h until the status flags clear; returns the OR of the flags seen), stores them in
0328:0581 and calls `seq_tick` 0328:0DDA, then unmasks. Initial timer values with the OPN clock of the
PC-9801-26 board (3.9936 MHz): timer A = (F7h<<2)|1 = 989 → 0.63 ms; timer B = DFh → 9.5 ms (**inferred**
arithmetic). Timer A is variable (tempo), timer B fixed; `seq_tick` processes note-length counters first
and envelope-style per-channel work only when the timer-B flag is set (**inferred** from the structure of
0DDA–0F7C; to be confirmed by the sequencer analysis).

After `opn_init`, `usdtrap_install` 0328:04E9 looks for the vector (14h or 15h) that points into this
segment and re-points it at the `USDtrap` stub 0328:0557, which is `jmp far cs:[0560]` → `opn_irq`.
Functionally it is just a signature in front of the handler.

### 9.4 Loading and starting a song (**verified**)

* INT F4h AH=00h reads the file to 2B0F:0000 (INT F2h AH=00h: no size check against the 3000h bytes
  reserved; NOVA's largest song is 3620 bytes). AH=01h → `usd_start_song` 0328:02F5 → `usd_bind_and_start`
  0328:02FE with DS:SI = file, ES:DI = track table (music 2B0F:5002, sound effects 2B0F:503E).
* `usd_bind_and_start` relocates the header in the track table copy and calls
  `seq_start(count, table far ptr, owner)` 0328:0BD1. Music and sound effects share the six hardware
  channels. A track with priority 0 always takes its channel; a track with priority p > 0 needs the
  channel idle or playing something of priority ≤ p, and if any track of the request is refused nothing
  is started (`0328:0D18`). `seq_stop(p)` 0328:0CA0: p = 0 stops all six channels (this is what INT F4h
  AH=02h does), otherwise only channels whose priority is ≤ p.
* Volume/fade (`seq_set_fade(period, step, flag)` 0328:0D96, INT F4h AH=05h BX,CX,DX): period ≠ 0 →
  every *period* ticks the master volume offset changes by *step* (signed); period = 0 → the offset is set
  to *step* directly (0 = full, −64 = FFC0h = silent as used by fade-in). How the offset is applied to FM
  total levels / SSG volumes is part of the sequencer (not analysed).

**.USO file header** (from the binding code, checked against all 28 files in `MUS/`):

| offset | size | meaning |
|---|---|---|
| 0 | word | always 1 in NOVA's files; not read by the music path |
| 2 | word | number of tracks T, 1..6 (0 or > 6 → refused). 6 in all files except NV15 (5) and NVSE02 (1) |
| 4 | word | number of table blocks K (2, or 1 when only one kind is needed) |
| 6 | 10·T | track records: byte channel (0–2 = FM 1–3, 3–5 = SSG 1–3; a channel may appear once, order is free), byte priority (0 in all files), word offset of the track's data relative to *base*, word + dword overwritten at load with the data segment and the far pointer of the matching table (the file holds leftover garbage there, e.g. `71 7A 00 00 38 52`) |
| 6+10·T | K blocks | each: word type (0 = table for FM tracks, non-zero — 3 in the files — = table for SSG tracks), word length L, L bytes. Block lengths are multiples of 39 for type 0 (FM voices, 39 bytes each, **inferred**) and of 30 for type 3 (SSG envelopes, **inferred**) |
| after blocks | word | length of the track data that follows (= file size − base in every file) |
| base | … | track data (sequencer byte code, not analysed) |

If a file has no block of one kind, the default table pointers given to `apiF4_80_Install` are used
(2B0F:507A–5080).

**Sound effects.** NVSE01–11.USO are ordinary song files in the format above. The bank format expected
by AH=10h/11h (`usd_start_bank_entry` 0328:02DD) is different: word count N, N words of offsets, entry i
being a song header located at file + offset[i] + 2. None of the files on the disks has that layout (worked
example: with NVSE01.USO in the SE buffer, AH=11h BX=0 computes entry = 3000h + 6 + 2, reads the "track
count" 5A3Fh there and fails with CF, nothing is played). NV.OVL does contain calls with AH=10h and 11h,
so whether NOVA's scripts play the NVSE files through the music path (AH=00h/01h) or really issue the SE
calls — which this driver would silently reject for these files — has to be settled on the interpreter
side (**open**, §11).

### 9.5 Joystick — INT F4h AH=20h (**verified** code, bit meanings **inferred**)

Writes OPN register 0Fh (port B) = C0h, reads register 0Eh (port A) → stick 2; writes 80h, reads → stick 1.
Values are inverted and masked to 6 bits (PC-98 convention: bits 0–3 up/down/left/right, 4–5 triggers).
Returns AL = stick 1 now, AH = stick 1 newly pressed since the previous call, BL = stick 2 now, BH =
stick 2 newly pressed. AX=BX=0 without sound hardware. No caller found in NOVA.

## 10. Differences between NOVA's build and the Dengeki Nurse build

Compared with `re-tools/advbios_map.py` (all 1019 comparable code labels of the reference match at the
same address) and a byte diff (**verified**):

* Code is identical instruction for instruction except for data addresses and **one byte**: 0290:0893 in
  `anim_step` compares the script character of slot 1 with `~` (7Eh) in NOVA and with `2` (32h) in Dengeki
  Nurse (slot 0 uses `~` in both). NOVA's build therefore has the two-frames-per-step escape working for
  both slots.
* Child program name: "NV.Ovl" (DS:00EE) instead of "Adv98V.Ovl" — 4 bytes shorter, which shifts
  DS:00F5–0282 by −4.
* User name "ＮＯＶＡぱんだはうす" (plain and inside the encrypted notice) instead of "電撃ナースPC-9801V";
  the notice checksum word differs accordingly. The banner checksum constant (A177h) is the same.
* Disk-change and critical-error texts are the neutral wording quoted in §8 instead of Dengeki Nurse's
  playful ones; the texts are shorter, so the rest of the initialised data and the whole BSS sit 2Ch lower
  (e.g. `OldIntF6Vec` DS:17FA vs 1826), and the image is 30h bytes shorter.
* No functional difference in any service was found.
